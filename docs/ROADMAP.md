# 持续成熟的 Studio

## 产品原则

用户描述要拍什么；工作室负责把制作步骤组织起来。默认界面不要求填写 API payload、
帧率、编码器或文件路径。任何自动生成都能预览、撤回、重新生成并追溯输入。

首版的成功标准不是某一条影片看起来不错，而是第二部影片也能独立完成同样流程。
不要为首片把特定 benchmark 数字、来源或艺术风格写死到项目管理逻辑中。

## 已落地的地基

项目 JSON / 原子保存 / 历史版本 → 来源与素材 → 分镜 → 确定性画面 → 配音与字幕 →
混音 → 冻结导出 → QA。Google 适配器与渲染器分离；provider 错误可以看见。

默认引导工作台一次突出一个下一步，完整编辑器按需展开。已实现个人连接配置、
Copilot / Gemini 导演切换、Nano Banana 与 Azure / 本地语音配置，以及不覆盖工作
配置的连接检查。已完成的电影直接播放和下载，避免重复渲染。

## 下一步，按真实作品反馈迭代

1. **导演体验**：已有单镜头自然语言改稿与实际静帧审片；继续增加分镜拖拽、时间点评论、更灵活样片区间与生成用量预估。
2. **画面一致性**：已有 bible 与连续性参考图；继续增加可锁定的角色 / 场景参考库、局部图像编辑、任务取消与恢复。
3. **声音设计**：逐段试听、读音词典、外部人声、可选 BGM 和音效素材、可视化音轨与混音。
4. **更丰富影片**：Three.js 的 Windows 本地 3D 渲染已完成隔离验证；用户现已请求《小马过河》3D 角色片，下一步以 Blender 补齐角色资产、绑定、表演和离线渲染，采用受控场景契约和共享时间线。已有 210 秒故事审阅稿；正式 Studio 目前仍为 2D，3D 草稿被明确隔离，避免生成冒充 3D 的输出。详见 [3D 实施草案](3D-ENGINE.md)、[代码探针](../research/code-doc-film.md) 与 [X 方法研究](../research/x-filmmaking-3d.md)。Pika / Seedance 等付费视频生成平台不在路线内。
5. **制作管理**：已实现分镜、画面和样片确认；继续增加素材授权字段、工程打包、影片版本对比、导出预设。
6. **发布协作**：用户明确需要后再增加账号、远端存储、云渲染与发布；保持本地模式可用。

## 工程改进优先级

已支持横屏 / 竖屏 1080p24 和渲染代码、素材哈希；先补 scene schema 的版本迁移，再扩展
其他比例和多轨时间线。不要让 UI 直接拥有渲染逻辑。继续增加针对项目数据、失败恢复与
实际用户流程的测试，不用大量快照测试替代视觉判断。
