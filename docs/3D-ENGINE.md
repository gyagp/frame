## 第一阶段范围

优先做空间关系明确的镜头：几何体与矩阵块、芯片／产品结构示意、数据流、简化地图与路线。
基础能力是透视或正交相机、预设灯光、材质、阴影、对象位移／旋转、升起／推进／环绕／跟拍。
精确数字、字幕与坐标图表保留为清晰的 2D 叠层；统计比较避免被透视误导。

Subgroup matrix 可以用概念矩阵块的协作、tile 数据移动、软件栈空间展开试用这条路线，
明确标注为计算示意，避免把构图当成真实 GPU 内部结构。原有实测数值和口径继续独立引用。

Blender 作为后续高质量离线渲染后端，用于更复杂材质、精细模型、烘焙模拟和需要更长渲染时间
的镜头。人物表演还需要角色、绑定、动画与制作资产，不能因接入 Blender 就宣称自动解决。

## 用户流程

用户仍然只描述故事与风格。可选的“空间表现”提供自动、2D、3D 三项；导演可以在同一部影片中
安排适合空间表达的 3D 镜头。相机坐标、材质参数、阴影贴图等放在精细调整中。

故事／分镜确认 → 旁白测时与时间轴编译 → 关键画面确认 → 有声短样片 → 样片确认 → 全片。
保留现有确认关卡、个人 provider 设置、历史版本、逐镜保存和断点续做。模型继续使用配置的
Copilot／GPT-6 Astra；旁白继续 Azure；Nano Banana 可用于美术方向与可选贴图，不承担三维几何。

## 工程边界

| 组件 | 必要变化 |
|---|---|
| 3D 场景契约 | 新版本数据结构：白名单对象、分组、局部坐标、材质、灯光、相机、关键帧和 seed；拒绝任意 JS、shader 字符串和外部 URL |
| 渲染适配器 | `renderAt(t)` 驱动固定 Three.js 场景；浏览器预览和离线捕帧使用同一实现；与已有 2D 运行时共用影片时间轴 |
| 语音 cue 编译器 | 支持有限的句首／句尾锚点与 0–1 镜内进度，不执行字符串表达式；用实际 WAV 时长编译可审阅时间轴 |
| 资产库 | 第一版可信程序化几何与场景组件；后续加入经过检查的本地 glTF、材质贴图、包围盒与来源记录 |
| 摄影保护 | 主体取景、相机与目标有效性、近远裁面、地表净空、已知遮挡和文字安全区；修正要有可见诊断 |
| 导出 | 本地浏览器捕帧 + FFmpeg，与现有字幕、音轨、封面、MP4 输出整合；支持单镜预览、取消与续做 |
| 缓存／版本 | 区分使用的渲染后端及其版本，把相关材质、模型、语音与时间轴纳入指纹；新增后端不主动重做既有已完成影片 |

三维运行时应是受控场景库；大模型选择和编排场景数据。研究中的上游 JS 示例可以在隔离测试里
运行，正式工程不能把“接受任意生成代码”当作新增能力的快捷方式。

## 依赖与验证

首先固定 Three.js 和浏览器版本。HyperFrames 是可选开源导出器，本机已证实基本渲染链不需要
依赖它；是否引入应根据吞吐、失败恢复、Windows 适配与维护成本判断。

实现后应验证：

- 同一时刻乱序取帧稳定，场景切换和资源释放后能重建；记录 GPU／浏览器环境，不承诺跨 GPU 字节相同。
- 相机目标和运动有叙事用途；三维对象不会因为坐标歧义出框、穿模或被字幕挡住。
- 每镜至少三个代表时刻及切镜附近的实际画面；检查黑帧、过曝、裁切、遮挡和标签可读性。
- 3D 视频与实测旁白、字幕、音乐段落同步，固定时长的作品提前完成音频预检。
- 单镜成本／耗时可见；重试保留已经完成的资产和镜头，最终仍由有声样片验证整体效果。

第二阶段再吸收地形数据、更多道具、分段配乐与环境声；第三阶段接 Blender。先让第二部、第三部
作品稳定复用同一个 3D 制作流程，再扩大题材与资产复杂度。
